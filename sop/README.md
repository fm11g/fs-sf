# SOP — 오늘의 정책자금 숏폼 공장

단계마다 md 파일 하나. **AI는 해당 단계를 실행·검수할 때 이 파일 전문을 지침으로 읽습니다.**
관리자 `[SOP·AI 제어]`에서 수정하면 즉시 다음 실행부터 반영되고(DB 저장 + 이력), `GitHub에 커밋`을 누르면 이 폴더 파일도 갱신됩니다.

| 파일 | 단계 | 산출물 | 기본 결정 방식 |
|---|---|---|---|
| 01-research.md | 조사 | 주제·공고 사실·출처 | 사람 |
| 02-plan.md | 기획 | 훅·40초 구성안 | 사람 |

## 파일 쓰는 법 (모든 단계 공통 구조)

```
# NN. 단계명
## 목적          — 이 단계가 끝나면 무엇이 결정되어 있어야 하는가 (1~2줄)
## 집중 포인트    — AI가 가장 먼저 봐야 할 것. 위에서부터 우선순위. ★ 여기를 가장 자주 고칩니다
## 체크리스트     — 통과/반려 기준. AI 검수와 사람 검수가 같은 목록을 씁니다
## 금지          — 하면 안 되는 것
## 사람이 결정할 것 — 검수 화면에서 사람이 고르는 지점
```

- 한 줄 = 한 지시. 이유가 필요하면 `— 이유`로 붙입니다.
- 산출물 JSON 형식·글자수 상한 같은 **기계 규칙은 코드에 고정**되어 있어 md를 고쳐도 깨지지 않습니다. md에는 "무엇에 집중할지"만 씁니다.
- 채널 성과를 보고 배운 것은 `집중 포인트` 맨 위에 날짜와 함께 추가합니다. 예: `- (11/20) 숫자 훅이 질문 훅보다 3초 유지율 높음 → 숫자 훅 우선`

## 자유도 (단계별 0~3)

| 값 | AI 행동 |
|---|---|
| 0 | SOP와 상위 산출물만 따름. 의견 최소화 |
| 1 | SOP 범위 안에서 작업, 개선 제안은 의견란에만 |
| 2 | SOP를 따르되 더 나은 표현·구성을 스스로 선택, 대안 2개 제시 |
| 3 | SOP는 가이드. 근거가 있으면 구성·각도를 바꿔도 됨. 바꾼 이유를 의견란에 기록 |

어떤 자유도에서도 **사실 정확성·금지 표현·글자수·JSON 형식**은 바뀌지 않습니다.

## 결정 방식 (단계별)

- `manual` 사람이 결정: 산출물이 `검수 대기`로 멈춤 → 승인 / 반려 / 피드백 재생성 / "AI에게 판단 맡기기"
- `ai` AI가 결정: AI 검수자가 체크리스트로 채점 → 통과면 자동 승인, 미달이면 피드백 반영해 1회 재작업 → 그래도 미달이면 사람에게 넘김
- `auto` 검수 없이 통과 (규칙 검사 오류가 있으면 멈춤)

상위 단계 산출물을 고치면 그것을 읽는 하위 단계는 자동으로 `재작업 필요`가 됩니다.
