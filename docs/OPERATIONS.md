## 작업대에서 할 수 있는 결정

| 버튼 | 결과 |
|---|---|
| 승인 | 이 산출물을 확정. 하위 단계가 이 값을 읽어 진행 |
| 승인하고 계속 진행 ▶ | 승인 후 다음 "사람이 결정" 단계까지 자동 진행 |
| 이 지시대로 재생성 | 입력한 지시를 반영해 이전 산출물을 고침 (나머지는 유지) |
| 반려(사유 저장) | 반려 사유가 다음 실행의 수정 지시로 자동 사용됨 |
| 🤖 AI에게 판단 맡기기 | AI 검수자가 SOP 체크리스트로 채점 → 통과면 승인, 미달이면 사유만 표시 |
| 🤖 AI 판단 + 자동 수정 | 미달이면 AI 피드백을 반영해 재생성까지 |
| 직접 수정 | 산출물을 손으로 고침 → 이 단계는 검수 대기, 하위 단계는 "재작업 필요" |

**상위 단계를 고치면** 그것을 읽는 하위 단계는 보라색 "재작업 필요"가 됩니다. "가능한 곳까지 자동 진행"을 누르면 순서대로 다시 만듭니다. 그대로 써도 되면 해당 단계를 열어 승인하면 됩니다.

## 결정 방식을 언제 바꾸나

| 신호 (작업 효율 화면) | 조치 |
|---|---|
| 어떤 단계의 "1회 통과율"이 2주간 90% 이상 + 사람이 고친 적 거의 없음 | 사람 → AI |
| AI 결정 단계에서 게시 후 문제가 발견됨 | AI → 사람, 문제를 SOP `체크리스트`에 추가 |
| 대기 시간(노랑 막대)이 가장 긴 단계 | AI로 전환하거나 결정 시간을 정해 두기 |
| 평균 시도 횟수가 1.5 이상 | 반복되는 반려 사유를 SOP `집중 포인트` 맨 위에 추가 |

권장 시작값: 01~04·09·10 사람 / 05~08 AI. 01(사실)과 09(영상)·10(공개)은 가능하면 계속 사람으로 둡니다.

## 자유도를 언제 바꾸나

| 상황 | 값 |
|---|---|
| 사실·규정이 중요한 단계 (조사, 이벤트) | 0~1 |
| 표현이 중요한 단계 (기획, 대사, 카피, 랜딩) | 2 |
| 새로운 포맷을 실험하고 싶을 때 (디자인, 기획) | 3 — AI가 구성을 바꾸고 이유를 "AI 의견"에 적음 |
| 결과가 들쭉날쭉할 때 | 한 단계 낮춤 |

## 좋은 결과물을 SOP 에 반영하는 법 (매일 몇 초)

작업대에서 마음에 드는 산출물은 **승인 + 👍** (메모란에 좋은 이유 한 줄), 별로인 것은 **👎 + 이유**. 직접 고친 뒤 승인하면 자동으로 학습 재료가 됩니다. 재료가 쌓이면 SOP 학습 제안이 메일로 오고, [SOP · AI 제어]에서 골라 반영합니다 → [LEARNING-NOTIFY.md](LEARNING-NOTIFY.md)

## 성과를 SOP에 반영하는 법 (주 1회)

1. 작업 효율 → 콘텐츠별 표에서 조회·신청·전환이 높은/낮은 편 3개씩 열기
2. 차이가 난 지점(훅 유형, 이벤트명, 헤드라인)을 찾기
3. 해당 단계 SOP `집중 포인트` 맨 위에 날짜와 함께 한 줄 추가
   예) `- (11/20) "이번 주 마감" 훅이 질문형보다 신청 전환 2배 → 마감 있는 공고는 마감 훅 우선`
4. 저장 → 필요하면 "GitHub에 커밋" (저장소의 `sop/*.md` 갱신)

## 문제 해결

| 증상 | 확인 |
|---|---|
| 단계가 "작업 중"에서 멈춤 | Vercel 함수 시간 초과 가능 → 다시 실행. 반복되면 Pro 플랜 또는 SOP 길이 축소 |
| 알림 메일이 안 옴 | 설정 → 최근 발송 기록의 오류 확인 → 테스트 메일. Gmail 은 앱 비밀번호 필요 |
| SOP 제안이 안 생김 | 설정의 학습 방식이 "끔"인지, 단계별 미반영 재료가 제안 기준 이상인지 확인. 지금 SOP 제안 만들기로 수동 생성 |
| `모든 AI 제공자 실패` | 설정 → AI 제공자 상태 확인. 급하면 에이전트에게 "직접 써서 제출해"(`tpf-step-local`) |
| 규칙 검사에 `제공자 전환` 경고 | 앞 순서 제공자가 실패해 다음 것으로 만든 결과. 품질을 한 번 더 확인 |
| 렌더가 시작되지 않음 | GitHub Actions 탭의 factory 워크플로 로그, `GITHUB_TOKEN` 권한 |
| 영상 길이가 35~45초를 벗어남 | 03 대사 글자수 조정 또는 설정의 말 속도 |
| 랜딩 문구가 잘림 | 템플릿의 `data-max` 를 실제 레이아웃에 맞게 조정 후 05 재실행 |
| 유튜브 업로드가 비공개로 됨 | API 감사 미통과 프로젝트 |
