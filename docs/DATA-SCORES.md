# 점수 · 태그 · 데이터 저장 (GitHub · 구글 시트) · 점수 기반 최적화

## 데이터가 어디에 저장되나

| 저장소 | 역할 | 무엇이 |
|---|---|---|
| Supabase | 운영 (관리자 화면이 읽고 씀) | 전부 |
| **GitHub `data` 브랜치** | 학습 데이터 원본 · 이력 | 모든 단계 실행(입력 지시문·출력·특징·검사·결정), 평가(등급별 폴더), 사람 수정 쌍, 학습용 데이터셋, 학습 노트, SOP 이력 |
| **구글 시트** | 보기 · 필터 · 분석 | outputs(모든 실행) · ratings(평가) · sop_changes · performance(매일 성과) 탭 |

이벤트(단계 완료·결정·평가·SOP 변경)가 생기면 내보내기 큐에 넣고 즉시 보냅니다. 실패한 건 남아서 매일 18시와 [설정 → 대기분 지금 보내기]에서 다시 보냅니다.

### GitHub `data` 브랜치 구조
```
data/
  runs/2026/11/<슬러그>/03-script-a2.json        모든 실행 (시도별)
  ratings/<단계>/gold|silver|neutral|negative/…   점수별 폴더 (★5 / ★4 / ★3 / ★1~2)
  pairs/<단계>/…                                  사람이 고친 예 (AI 원본 ↔ 최종본)
  datasets/<단계>/sft.jsonl                       ★4 이상 · chat 형식 → 미세조정용
  datasets/<단계>/preference.jsonl                사람 수정 쌍 → 선호 학습(DPO)용
  datasets/<단계>/negative.jsonl                  ★2 이하 + 이유
  index/ratings.csv · index/summary.json          모든 평가 한 표 · 단계별 요약
  learnings/<NN-단계>.md                          지금까지의 학습 노트
  sop/<NN-단계>.md · sop-history/<단계>/…          현재 SOP · 변경 전/후 전문
```
- 코드(main)와 브랜치가 분리되어 배포·CI에 영향이 없습니다(`vercel.json` 에서 data 브랜치 배포 끔).
- 다른 저장소에 두려면 설정 → 데이터 저장 → 저장소(owner/repo) 지정 (+ 필요하면 `GITHUB_DATA_TOKEN`).

### 구글 시트 연결 (둘 중 하나)
- **A. 서비스 계정** — Google Cloud 에서 서비스 계정 키(JSON) 발급 → Vercel `GOOGLE_SERVICE_ACCOUNT_JSON` 에 JSON 전체 → 시트를 서비스 계정 이메일에 "편집자"로 공유 → 설정에 시트 ID
- **B. Apps Script** (GCP 없이) — 시트에서 [확장 프로그램 → Apps Script] → `integrations/google-sheets/Code.gs` 붙여넣고 SECRET 변경 → 웹 앱으로 배포(액세스: 모든 사용자) → 설정에 웹앱 URL·비밀값
- 저장 후 "시트 테스트" → `connection_test` 탭이 생기면 정상

시트 열: 점수 · 등급 · 내 태그 · 메모 · 제공자 · 모델 · SOP 버전 · 그리고 **특징 태그가 열마다 분리**(hook_type · mood · scenes · chars · has_deadline · title_has_number …)되어 필터·피벗으로 "어떤 조건에서 점수가 높은지" 바로 볼 수 있습니다.

## 점수와 태그

작업대의 **결과물 평가** 카드: ★1~5 · 좋은 점(+)/아쉬운 점(−) 태그 · 직접 태그 · 이유 → "평가 저장" 또는 "평가 + 승인".

| 점수 | 등급 | 쓰임 |
|---|---|---|
| ★5 | gold | 참고 예시 1순위 · SOP 학습 근거 · sft 데이터셋 |
| ★4 | silver | 참고 예시 · SOP 학습 근거 · sft 데이터셋 |
| ★3 | neutral | 통계에만 |
| ★1~2 | negative | "피할 것"으로 생성 프롬프트·SOP 학습에 · negative 데이터셋 (이유 필수) |

평가할 때 자동으로 붙는 **특징 태그**: 제공자·모델·SOP 버전(내용 해시)·자유도·후보 수·결정 방식 + 단계별(기획: 훅 유형·무드·장면 수 / 대사: 글자수 구간·첫 문장 숫자 / 이벤트: 마감 유무·혜택 수 / 카피: 제목 숫자 …). 생성 당시 지시문(system·prompt)도 함께 저장되어 그대로 학습 데이터가 됩니다.

## 점수로 결과물을 최적화하는 방법

1. **참고 예시 주입** — 생성할 때 그 단계의 고득점(기본 ★4 이상) 예시 2개와 낮은 점수 이유를 프롬프트에 넣습니다. 사실·숫자는 가져오지 말고 구성·표현만 참고하도록 지시합니다(조사 단계는 이유 메모만). 설정 → 참고 예시 수 / 최소 점수.
2. **후보 여러 개 중 선택** — [SOP · AI 제어]에서 단계별 "후보 수"를 2~4로 두면 후보를 만들고, 내가 실제로 매긴 점수·이유를 기준으로 각 후보의 점수를 예측해 가장 높은 것을 고릅니다. 작업대에 "AI 예측 ★4.3 · 후보 3개 중 선택"으로 표시. 비용은 후보 수만큼 늘어납니다.
3. **SOP 최적화** — 아래.

## 점수로 SOP md 를 최적화하는 방법

모든 SOP 작업은 먼저 **학습 노트**(지금까지의 학습)를 읽습니다:
점수 현황 · SOP 버전별 평균 점수 · 점수를 올린/내린 조건(태그·특징별 평균 대비) · 반영된 학습(시간순) · 거절된 제안과 이유 · 높은/낮은 점수 이유 · 반려·수정 이유.

| 방법 | 언제 | 결과 |
|---|---|---|
| 보완 제안 | 미반영 ★4 이상·수정 예가 기준 개수만큼 쌓이면 자동, 또는 버튼 | 줄 단위 추가·수정·삭제 (변경별 선택·문구 수정·되돌리기) |
| 🧹 SOP 재정리 | 직접 실행 (SOP 가 길어지거나 겹칠 때, 몇 차례 보완 후) | 누적 학습으로 다시 정리한 SOP 전문 + 변경 기록 → 전후 비교 → 다듬어 반영 |

재정리 안전장치: 섹션 구조 유지 · ## 금지 항목이 빠지면 자동으로 되살림 · 금지 표현이 있으면 폐기 · 분량이 크게 늘거나 줄면 경고 · 자동 반영 없음 · 그 사이 SOP 가 바뀌면 강제 반영을 따로 선택해야 함.

효과 확인: 반영하면 SOP 버전(해시)이 바뀌고, 이후 평가가 새 버전으로 집계됩니다 → [SOP · AI 제어] 학습 패널의 "SOP 버전별 평균"으로 나아졌는지 봅니다.
