# 영상 디자인 — 언론사 템플릿 · 스타일 · Claude 모션 · 자막

## 1. 언론사 템플릿 (기본)
새로 만드는 디자인은 `news` 템플릿으로 나옵니다. 예전 디자인은 `classic`으로 남고, 디자인 단계를 다시 돌리거나 편집기에서 스타일을 적용하면 바뀝니다.

| 레이아웃 | 쓰는 곳 |
|---|---|
| breaking | 첫 장면. 속보 태그와 큰 헤드라인 |
| headline | 핵심 문장 한 줄 |
| stat | 숫자 카운트업. **출처 필수** |
| list | 요점 2~4개 |
| compare | 둘 비교. 항목은 `라벨\|내용` 정확히 2개 |
| quote | 공고문·관계자 인용 |
| document | 공문서 카드 (기관·문서명·발췌) |
| timeline | 일정. 항목은 `날짜\|내용` |
| cta | 마지막 장면. 신청 안내 |

화면 요소: 채널 표시(bug), 날짜, 진행선, 티커(선택), 격자 배경, 출처 줄. 안전 영역은 y 290~1360입니다.

## 2. 영상 스타일 (`/admin/styles` — 왼쪽 메뉴 [영상 스타일])
- **기본 프리셋 3종**: 언론사·네이비(기본), 언론사·지면(화이트 · 명조 제목), 언론사·속보(블랙 · 빨강 · 티커).
- **레퍼런스로 새 스타일 만들기**
  - 입력: 마음에 드는 채널의 캡처(최대 6장, 끌어놓기·붙여넣기 가능), 유튜브 쇼츠 링크, 또는 [참고 영상]에서 분석이 끝난 영상.
  - 분석: Claude(작업 `style`, 비전)가 색, 폰트·굵기, 자막 모양, 화면 구성 규칙, 모션 성향을 뽑습니다.
  - 확인과 저장: 샘플 영상(레이아웃 9종)으로 바로 미리 본 뒤 저장합니다.
  - 유튜브 링크는 썸네일만 보여서 대략적입니다. 정확하게 하려면 참고 영상 프레임을 쓰세요.
  - 인스타그램은 로그인이 필요해서 캡처로 올려야 합니다.
- **기본으로 지정**: 이후 디자인 단계가 그 스타일의 규칙·색·폰트·자막으로 영상을 만듭니다.
- **콘텐츠마다 바꾸기**: 편집기 [스타일·전체] 탭에서 다른 스타일을 고를 수 있습니다.
- **편집기에서 저장**: 편집기에서 다듬은 디자인도 [스타일로 저장]하면 재사용할 수 있습니다.

## 3. Claude 모션 (편집기 [모션] 탭)
- 장면마다 "Claude 에게 모션 요청" 칸에 원하는 연출을 적습니다. 예: "60억 숫자를 크게 카운트업하고 밑줄이 그어지게".
- Claude(작업 `motion`, Opus)가 레이어를 만들어 줍니다.
  - 레이어 종류: text, tag, box, line, highlight, counter, bar, image, emoji.
  - 등장·퇴장: fade, slide(상하좌우), scale, pop, wipe(4방향), blurIn, typewriter, countUp, grow. 시작 시점, 길이, 이징을 정합니다.
  - 그 밖에 키프레임, 반복, 앞뒤 순서(z)를 지정합니다.
- 레이어는 목록에서 바로 고치거나 미리보기에서 끌어 옮길 수 있습니다. JSON으로 직접 편집해도 됩니다.
- 디자인 단계 AI도 같은 레이어 규칙으로 장면마다 모션을 넣습니다.

## 4. 자막 (편집기 [자막] 탭)
- **전체 설정**
  - 모양: 하단 자막 / 띠 / 박스 / 글자만
  - 라벨 탭과 색
  - 글꼴과 굵기 (해당 글꼴에 실제로 있는 굵기만 표시)
  - 정렬, 크기(px), 글자색·강조색
  - 바탕색과 투명도, 여백, 모서리, 왼쪽 강조 막대
  - 외곽선, 그림자, 줄간격, 자간, 최대 폭, 바닥에서 높이
  - 애니메이션: 없음 / 페이드 / 팝 / 슬라이드 / 와이프 / 단어별 / 가라오케
- **장면별 덮어쓰기**: 색, 바탕, 굵기, 정렬, 숨김.
- **강조**: 장면의 강조 단어(emphasis)가 자막에서도 강조색으로 나옵니다.

## 5. 글꼴
- 언론·공식: Pretendard, Noto Sans KR, Noto Serif KR, IBM Plex Sans KR
- 고딕: Gothic A1, 나눔고딕
- 명조: 함렛, 나눔명조, 고운바탕
- 제목: 검은고딕, 도현, 가석, 해바라기
- 개성: 주아, 고운돋움, 동글, 나눔손글씨 펜

렌더 워커는 `worker/scripts/fonts.sh`로 굵기별 파일을 받아 씁니다.

## 6. 렌더 진행 상황 (작업대 [09 렌더])
[렌더 시작]을 누르면 작업대에 진행 패널이 열리고 2초마다 갱신됩니다.
- **진행 바와 전체 %**: 구간 10개로 나뉘며, 구간 폭은 그 단계가 걸리는 비중입니다. 지금 진행 중인 구간은 줄무늬로 움직이고, 실패한 구간은 빨강입니다.
- **지금 하는 일**: 단계 이름, 그 단계의 %, 세부 내용. 예: `540/1134 프레임 · 장면 5/9 (compare) · 31fps`
- **단계 목록**: 요청 접수 → 렌더 서버 준비(설치·폰트·브라우저) → AI 목소리 → 배경음악 → 모션 준비 → 프레임 그리기 → 인코딩·합성 → 썸네일 → 업로드 → 검사·결정. 단계마다 걸린 시간과 결과가 붙습니다.
- **장면별 작업**:
  - 장면마다 목소리 상태(🎙)와 길이를 보여 주고, 만들어진 목소리는 바로 들어 볼 수 있습니다.
  - 장면별 프레임 그리기 진행 막대가 있고, 지금 그리는 장면은 파랗게 강조됩니다.
- **만들어진 썸네일**: 썸네일이 하나 만들어질 때마다 바로 나타납니다.
- **작업 로그**: 시각, 단계, 내용이 실시간으로 쌓입니다. 경고는 노랑, 오류는 빨강입니다.
- **남은 시간**: 워커가 시작된 뒤의 속도로 추정합니다. `GitHub 실행 화면 ↗` 링크로 Actions 로그도 바로 열 수 있습니다.
- **알림**: GitHub Actions 가 4분 넘게 시작하지 않거나, 렌더 중에 2분 반 넘게 소식이 없으면 경고가 뜹니다.
- **실패하면**: 멈춘 단계와 실제 사유가 남습니다. 설치 단계에서 실패해도 표시됩니다.
- **현황판**: 렌더 중인 카드에 작은 진행 막대와 %가 붙고, 렌더 중일 때는 4초마다 새로고침됩니다.
- **중복 요청 방지**: 이미 렌더 중이면(3분 안에 갱신된 기록이 있으면) [렌더 시작]을 다시 눌러도 막힙니다.

구조:
- 워커는 `worker/src/progress.ts`로 `contents.render_progress` 를 1.2초에 한 번 저장합니다.
- 설치 단계(Node 시작 전)는 `worker/scripts/progress.sh` 가 Supabase 함수 `render_progress_patch` 로 기록합니다.
- 단계 정의는 `worker/video/stages.ts` 하나를 워커와 화면이 함께 씁니다.

## 7. 강제 중지 · 자동 정지
**강제 중지**
- **AI 단계 (조사~게시글)**:
  - 작업 중이면 작업대 위에 진행 줄이 뜹니다. 경과 시간, 자동 정지까지 남은 시간, 시간 막대, **[■ 중지]**가 보입니다.
  - 중지하면 '작업 중' 표시가 바로 풀리고(3초 안), 늦게 도착한 AI 결과는 저장하지 않습니다.
  - **[■ 자동 진행 멈춤]**: '가능한 곳까지 자동 진행' 중에 누르면 지금 단계를 중지하고 반복도 멈춥니다.
- **렌더**: 진행 패널의 **[■ 렌더 중지]**를 누르면 세 가지가 함께 일어납니다.
  1. GitHub Actions 실행을 취소합니다. 아직 대기 중인 실행도 실행 제목의 요청값으로 찾아 취소합니다.
  2. 워커에 중지 신호를 보냅니다. GitHub 취소가 안 되더라도 워커가 4초 안에 스스로 멈춥니다.
  3. 진행 패널은 '렌더 중지됨'으로 바뀌고, [다시 렌더]로 새로 시작할 수 있습니다.
  - GitHub 취소에는 토큰의 **Actions 쓰기 권한**이 필요합니다. 없으면 로그에 안내가 남고, 워커가 스스로 멈춥니다.

**자동 정지** (기준은 [설정]에서 변경)

| 설정 | 기본 | 동작 |
|---|---|---|
| `step_timeout_sec` | 280초 | AI 단계 1회가 이 시간을 넘으면 서버가 멈추고 '시간 초과로 자동 정지'로 기록. 서버가 강제 종료돼 기록을 못 남긴 경우도 +60초 뒤 정리 |
| `render_timeout_min` | 30분 | 렌더 전체가 넘으면 정지 |
| `render_stall_sec` | 240초 | 렌더가 이 시간 동안 한 걸음도 안 나가면 정지 (프레임·목소리·업로드 어디서든) |
| `render_queue_min` | 15분 | GitHub Actions 가 이 시간 안에 시작하지 않으면 정지 |

- 워커 안의 감시견이 4초마다 확인합니다. Remotion 렌더는 즉시 취소되고, 목소리(TTS) 요청은 90초 응답 제한이 있습니다.
- 워커가 죽어 기록이 끊긴 경우: 작업대·현황판·진행 조회·매일 크론이 열릴 때 서버가 정리합니다(30초에 한 번).

구조:
- 사이트: `lib/stop.ts`, `app/api/stop`.
- 워커: `worker/src/watchdog.ts`. 기준값 정의는 `worker/video/limits.ts`.
- DB: `contents.cancel_requested_at`(013).
